Method

How the benchmark ran

Protocol

  • Answers: the saved answers of ../enterpriserag-bench/runs/2026-10-10_gptoss-pilot, linked, not made again (EnterpriseRAG-Bench commit d36685e27371).
  • Questions: the 50-question pilot, stratified by question type, seed 42. References: the gold answer, the gold facts and the gold document IDs of each question.
  • Scorer: pipeline/score_extra.py with configs/scorers/v2_haiku-nothink.json (sha256 e26216a32c2b); judge anthropic-claude-haiku-5-5-nothink, {"temperature": 0, "max_tokens": 4096}.
  • Summarization assessment questions are made once per question and are the same for every system.
  • Packages: ragas 0.4.3, deepeval 4.2.8, openai 1.109.1.

Systems

  • 4Minds (Constellations): 4Minds prod, Constellations engine (WebSocket), GPT-OSS-120B served by 4Minds; one file per document.
  • 4Minds (benchmark system prompt, local): 4Minds on the operator's local stack (minikube, branch vb/evals at 51f9f51df plus one local edit), Constellations engine (WebSocket), the same GPT-OSS-120B endpoint as prod; the persona's behavioral guidelines (the official EnterpriseRAG-Bench prompt) replace the 4Minds response system prompt.
  • GPT-OSS + LangChain: LangChain TokenTextSplitter (512 tokens, 10% overlap), text-embedding-3-large, FAISS; 100 chunks to the top 10 full documents; the official answer prompt; GPT-OSS-120B on Amazon Bedrock.
  • GPT-OSS + GraphRAG: Microsoft GraphRAG 3.3.0, fast indexing method with default settings, local search (community level 2), text-embedding-3-large; GPT-OSS-120B on Amazon Bedrock.
  • GPT-OSS + GraphRAG (standard): Microsoft GraphRAG 3.3.0, standard indexing method with default settings (LLM entity and relationship extraction and community reports by GPT-OSS-120B), local search (community level 2), text-embedding-3-large; GPT-OSS-120B on Amazon Bedrock.
  • GPT-OSS + RAGFlow: RAGFlow v0.27.2 (self-hosted), naive chunking (512 tokens), text-embedding-3-large; the retrieval API with the default chat-assistant settings (6 chunks, hybrid search); GPT-OSS-120B on Amazon Bedrock.
  • GPT-OSS, no RAG: GPT-OSS-120B on Amazon Bedrock with the official answer prompt and an empty Context Documents section (world-knowledge baseline).
Read before you share

Notes and caveats

  • Pilot: 50 of 500 EnterpriseRAG-Bench questions, stratified by question type (2 to 17 per type), on a 10,000-document corpus slice. The judge is not fully repeatable. Do not rank systems from small differences.
  • Not an official protocol: these are 4Minds RAG metrics on the saved answers of the EnterpriseRAG-Bench run. The systems did not answer again. The references are the EnterpriseRAG-Bench gold answer (Answer Accuracy, Factual Correctness), gold facts (Summarization, Hallucination) and gold documents (document retrieval).
  • Summarization: the 'original text' is the gold facts of the question, not the retrieved context. The score shows how well the answer covers the gold facts (coverage) without statements that the facts do not support (alignment); score = min(alignment, coverage).
  • Hallucination: DeepEval checks the answer against each gold fact. The score is the fraction of facts with the verdict 'agrees' (higher is better). The DeepEval prompt says that missing detail is not a contradiction, but the judges often give 'does not agree' to an answer that says the documents do not have the information; so a non-answer scores 0 for most questions and 1 for some (No RAG has 27 non-answers: 22 score 0 with gpt-4o-mini, 18 with Haiku). Read it together with Answer Accuracy and Factual Correctness. (The note in the scorer configs says that 'I don't know' scores 1; that is the intent of the prompt, not what the judges did.)
  • Two kinds of precision, recall and F1: Factual Correctness counts claims (claims of the answer supported by the gold answer, and claims of the gold answer found in the answer; judge). Document retrieval counts document IDs (the documents the system gave against the gold documents; no judge, exact match).
  • Document retrieval uses the original gold documents (no correction step, unlike the official EnterpriseRAG-Bench scorer) and only the 46 questions that have gold documents. Systems that give many documents get a lower precision.
  • Haiku judge: the Anthropic OpenAI-compatible endpoint rejects the RAGAS response_format {"type": "json_object"} (HTTP 400), so the scorer config removes that field (drop_params). The prompt with the JSON schema is the same; Haiku puts the JSON in a code fence, which the scorer removes before parsing (about 340 fences per system). gpt-4o-mini got the field.
  • Haiku judge: the first pass hit the rate limit of 80,000 output tokens per minute (HTTP 429) at 16 parallel requests; two retry passes, the same for every system, scored all such items. 4 items stay not scored, and they are not in the means: Summarization of qst_0454 for LangChain, RAGFlow and GraphRAG (the answer is only a date, and Haiku replied in prose that the text to extract claims from was empty; audit step diagnose_v2_qst_0454), and Factual Correctness of qst_0433 for RAGFlow (the claim list was longer than the 4,096-token limit). GraphRAG (standard) was scored later with one retry pass; all its items are scored, including Summarization of qst_0454.
  • 4Minds: the document IDs come from the chunk document_title (file name <dsid>_<title>.txt), in chunk score order.
  • 4Minds local: not the prod release. Local edit in constellations/assembler/prompts/preliminary_response_prompt.py: when the persona has behavioral guidelines, they replace PRELIMINARY_RESPONSE_SYSTEM (which asks for markdown and bold). The rest of the 4Minds prompt stays, including the DOCUMENT SUMMARIES section ('structure your coverage'); the stored document summaries are markdown. 26 of 50 answers have bold text (prod: 43 of 50).
  • 4Minds local: qst_0027 has no context. The Graph Engine timed out (15 s) on the local stack, and the system answered without chunks; prod had 10 chunks for this question. The answer is kept and scored.
  • 4Minds local, v2 run (Haiku): the first pass hit the rate limit (HTTP 429) on 17 items and then hung on its last request; it was stopped, and two retry passes (the same as for the other systems) scored all 246 items. The judge usage of the first pass was not saved, so the judge cost of this row in the v2 run is too low.
  • 4Minds local: the build status was still 'enhancing' during the answers (document summaries still being written), so the number of summaries in the prompt can differ between questions.
  • LangChain: always gives 10 documents, so its document precision is at most 0.1 for a question with one gold document.
  • GraphRAG: this row is not representative of GraphRAG. The fast method writes no entity descriptions, so local search compares the question only with entity names. On a 500-document test, the standard method found 52 of 74 gold documents and the fast method 17 of 74 (see the EnterpriseRAG-Bench run README). The row GPT-OSS + GraphRAG (standard) uses the standard method on the same slice.
  • GraphRAG (standard): 53 of 21,727 communities (0.24%) have no report because the reply stayed invalid JSON. The index, the answers and the scores were made on victormini1 with the same code, settings and scorer configs; its scoring environments use the package versions of envs/pip_freeze_extra.txt.
  • GraphRAG (standard), v1 run (gpt-4o-mini): the first scoring pass hung on one request (Summarization of qst_0007) and was stopped; a second pass scored that item. The judge usage of the first pass was not saved, so the judge cost of this row in the v1 run is too low.
  • No RAG: the system gets no documents, so all its document scores are 0 by design. It has 49 answers; the question without an answer is not scored.

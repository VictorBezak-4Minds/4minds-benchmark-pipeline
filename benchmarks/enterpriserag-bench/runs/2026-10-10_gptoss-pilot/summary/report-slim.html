EnterpriseRAG-Bench · PILOT

Benchmark: onyx-dot-app/EnterpriseRAG-Bench on GitHub

Does 4Minds answer questions about a company's own documents better than the RAG systems that customers already use? 8 systems with the same model (GPT-OSS-120B) answered the same 50 questions from the same 10,000 company documents. The official EnterpriseRAG-Bench scorer, with its own judge (gpt-5.4), scored each system alone.

Not scored

Systems and questions without a result

When a system did not give an answer to a question, the official scorer skipped that question. The official averages do not include these questions. The column “Overall, missing = 0” in the table above counts each of them as 0.

  • Gemini + File Search (first run): 8 of 50 questions skipped. For each of these questions, Gemini made searches for 90 to 120 seconds, and then the Gemini API stopped the request with the error “Model generated too many tool calls”.
  • Gemini + File Search (3 attempts)*: 6 of 50 questions skipped. Each of these questions got 3 attempts, and each attempt stopped with the same “too many tool calls” error.
  • GPT-OSS, no RAG: 1 of 50 questions skipped. This system gets no documents, and for this question the model gave an empty answer because it had no documents to answer from.

Method

How the benchmark ran

Protocol

  • Dataset: EnterpriseRAG-Bench (Onyx), commit d36685e27371, 511,958 documents and 500 questions.
  • Pilot: 50 questions, stratified by question type, seed 42.
  • Corpus slice: the 74 gold documents of the pilot questions plus 9,926 random other documents (48,872,100 characters).
  • Every system got the same documents and the instructions of the official answer prompt.
  • Scoring: the official metrics_based_eval.py, unchanged, with its default settings and judge (gpt-5.4; gpt-5-mini for JSON recovery).
  • No system answered a question before its ingestion was complete (a readiness check gates each run).

Systems

All “GPT-OSS” systems use GPT-OSS-120B on Amazon Bedrock and the official answer prompt. The GPT-OSS systems with retrieval also use text-embedding-3-large embeddings.

  • 4Minds: 4Minds full end-to-end system. Leaderboard name: “4Minds system”.
  • GPT-OSS + LangChain: LangChain plain vector search. The model gets the 10 best full documents. Leaderboard name: “LangChain vector (text-embedding-3-large) + GPT-OSS-120B”.
    Exact settingsTokenTextSplitter (512 tokens, 10% overlap), FAISS; 100 chunks to the top 10 full documents.
  • GPT-OSS + GraphRAG: Microsoft GraphRAG 3.3.0, fast method. A low-cost graph made from noun phrases. Leaderboard name: “Microsoft GraphRAG 3.3.0 fast, local search (text-embedding-3-large) + GPT-OSS-120B”.
    Exact settingsFast indexing method with default settings (1,200-token chunks, noun-phrase graph, community reports by GPT-OSS-120B); local search context (community level 2).
  • GPT-OSS + GraphRAG (standard): Microsoft GraphRAG 3.3.0, standard method. A knowledge graph that the LLM builds. Leaderboard name: “Microsoft GraphRAG 3.3.0 standard, local search (text-embedding-3-large) + GPT-OSS-120B”.
    Exact settingsStandard indexing method with default settings (1,200-token chunks, LLM entity and relationship extraction, description summaries and community reports by GPT-OSS-120B); local search context (community level 2).
  • GPT-OSS + RAGFlow: RAGFlow v0.27.2 (self-hosted). Keyword and vector search together, with default settings. Leaderboard name: “RAGFlow v0.27.2 hybrid search (text-embedding-3-large) + GPT-OSS-120B”.
    Exact settingsNaive chunking (512 tokens, DeepDOC); POST /api/v1/retrieval with the default chat-assistant settings (6 chunks, hybrid keyword + vector search with vector weight 0.3, similarity threshold 0.2, no reranker).
  • Gemini + File Search (first run): gemini-3.8-flash with Google's hosted File Search tool, with default settings. Leaderboard name: “Gemini File Search (gemini-3.8-flash), first run”.
    Exact settingsGemini Developer API (Interactions API); top_k 5 per search; Gemini default temperature and thinking level; one store file per document with the File Search default chunking and embedding; the official instructions as the system instruction.
  • Gemini + File Search (3 attempts)*: The first run of Gemini + File Search, with up to two more attempts for the questions that failed. Leaderboard name: “Gemini File Search (gemini-3.8-flash), 3 attempts”.
    Exact settingsSame settings as the first run; the third attempt with a 300 s client timeout.
  • GPT-OSS, no RAG: an empty Context Documents section, so the model uses only its own knowledge (world-knowledge baseline). Leaderboard name: “GPT-OSS-120B, no retrieval”.
Terminology

EnterpriseRAG-Bench · metrics-based

Official metrics_based_eval.py at commit d36685e, unchanged, default settings. Judge gpt-5.4 (gpt-5-mini only for JSON recovery). Each system is scored alone; the leaderboard Space's transform_raw_data.py makes the rows.

MetricUsed onWhyHow
Overall scoreAll questions (headline, leaderboard column)One number that needs a correct answer and rewards a complete one. The public leaderboard sorts by it.Per question: completeness if the answer is correct, else 0. Mean over the scored questions. RecallQuestions with gold documentsDid the system find the documents that have the answer? Needs the document IDs that the system used.Gold documents in the system's document list / all gold documents.
Invalid extra docsQuestions with gold documentsShows a system that returns many documents to raise its recall. Lower is better; it is a count, not 0–100.Number of returned documents that are not gold and not marked "valid" (relevant) for the question.
